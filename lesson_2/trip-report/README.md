## Команды (Windows / PowerShell)

Создать окружение:
```
python -m venv .venv
```

Активировать окружение:

```
.venv\Scripts\Activate.ps1
(Если PowerShell выдаёт ошибку политики выполнения, один раз выполните: Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser)
```

Поставить зависимости:

```
python -m pip install rich
```

Запустить программу:

```
python -m app.main
```

Прогнать тесты:

```
python -m unittest discover -s tests -v
```

## Почему .venv не кладут в репозиторий

Папка .venv содержит файлы конкретной операционной системы, конкретной версии Python и ссылки на абсолютные пути на моём компьютере. Если её закоммитить:
- репозиторий раздуется на десятки мегабайт мусора;
- у другого разработчика на macOS или Linux окружение просто не запустится;
- при обновлении зависимостей придётся каждый раз коммитить тысячи изменённых файлов.

Правильный подход — хранить в репозитории только список зависимостей (requirements.txt), а окружение каждый разработчик создаёт у себя локально одной командой python -m venv .venv.
